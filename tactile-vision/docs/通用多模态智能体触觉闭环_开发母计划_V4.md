# 通用多模态智能体触觉闭环｜开发母计划 V4

状态：**当前唯一有效主计划**  
日期：2026-09-23  
替代：V3 及更早的设备无关几何、本地语义栅格化、固定 Grounding/边缘路线

## 产品定义

```text
任意图片
→ qwen3.8-max 触觉智能体
→ 模型直接决定完整 80×48 UInt8 高度与区域矩阵
→ 机械工具校验并把精确错误返回模型
→ 模型查看实际预览，自主接受或整帧重做（最多三个候选）
→ PC 与 RDK 发布同一 checksum 的权威帧
→ 动态升起、触摸语音、连续追问、落下与复用
```

模型是内容、空间和每一个 pin 的唯一决策者。本地不根据框、轮廓、布局描述或传统视觉算法生成第二张矩阵。

## 硬件契约与模型输出

- 固定设备：`rdk_hdmi`，横向 80 列、纵向 48 行，共 3840 点。
- 高度：`UInt8 0..255`；0 完全落下，255 最大升起。
- 权威帧包含 `height_rows`、`region_rows`、regions、整图说明、语音概览、frame id、时间和 SHA-256 checksum。
- 模型可使用逐行无损 RLE 提交，工具只机械展开成完整 48×80 矩阵，不补点、不截断、不推断语义。
- 每个升起点必须带模型定义的非零 region id；触摸直接查 `region_rows`。

## 智能体循环

一个候选内部由同一模型先输出 manifest，再分块直接提交全部硬件行；manifest 只帮助模型保持空间一致性，本地绝不据此栅格化。

工具职责：

1. `submit_tactile_candidate`：检查行列、范围、区域引用和完整性，返回精确字段路径。
2. `render_tactile_preview`：按模型高度原样渲染 80×48 顶视预览。
3. `publish_tactile_frame`：只发布模型接受且机械合法的完整帧。

最多三个完整候选。协议错误返回模型修复；语义好坏只由模型结合原图与实际预览判断。三次仍失败则保留最近合法帧，没有历史帧时维持落下状态。

## 产品与运行时

- PC 单一产品页：上传、附加要求、真实进度、动态表面、落下/重放、触摸、语音、追问。
- 开发信息折叠显示候选、工具错误、完整帧和 RDK 地址；产品区不显示 GroundedScene/YOLO/边缘固定关卡。
- RDK `/display.html` 只订阅统一运行时事件，按相同 frame id/checksum 展示，不调用模型、不生成矩阵。
- 统一接口：`POST /api/agent/runs`、run SSE、`GET /api/runtime/frame`、runtime SSE、`POST /api/surface/actions`、`POST /api/touch`。
- 旧 `/api/understand`、`/api/plan`、`/api/compile` 退出产品主链；`GET /api/live-frame` 仅保留兼容快照。

## 验收标准

- 任意图片的最终 3840 点来自模型权威候选，不经过本地语义编译。
- 验证器准确指出协议问题且不修改输入。
- PC/RDK 的 frame id 和 checksum 一致，支持升起、落下、重放与断线恢复。
- 每个升起点可触摸解释，支持当前图片和位置上下文的连续问答。
- 失败不发布假帧、不覆盖最近合法帧，密钥不进入页面、日志或状态接口。
- 通用回归覆盖人物、动物、室内、街景、建筑、植物、商品、文档/UI、地图/图表、线稿/插画与复杂背景。

## 明确禁止

- 用 DeviceCompiler、浏览器算法或传统视觉管线替模型决定最终点位；
- 把检测、分割、边缘、深度设为每张图片必经步骤；
- 使用 synthetic/旧帧冒充本轮模型成功；
- 写死 4096、64×64、四级高度或二值高度；
- PC 与 RDK 各自产生不同矩阵；
- 瞬间替换而不展示真实升降过程。
