## 0. 产品定义

一句话：

> 把任意一张真实图片，先理解成完整的空间场景，再自动设计成适合手去探索的触觉结构，并根据不同触觉设备编译成对应的高度矩阵。

这个产品不是：
- 边缘检测器；
- 图片转黑白点阵；
- YOLO 检测框可视化；
- 固定人物 / 宠物 / 街景分类器；
- 只适用于几个预定义场景的算法。

这个产品必须满足：

```text
ANY IMAGE
    ↓
MULTIMODAL UNDERSTANDING
    ↓
GROUNDED SCENE
    ↓
TACTILE PLANNING
    ↓
TACTILE SCENE
    ↓
DEVICE COMPILER
    ↓
PHYSICAL / VIRTUAL TACTILE SURFACE
```

# 1. 不可违背的产品约束

## 1.1 输入域开放

系统不建立“人物模式 / 街景模式 / 商品模式”。

正常图片统一进入同一条主链，包括但不限于：

- 人物照；
- 动物；
- 室内；
- 街景；
- 建筑；
- 风景；
- 商品；
- 食物；
- UI 截图；
- 文档；
- 地图；
- 图表；
- 插画；
- 线稿；
- 抽象图像。

不同图片允许触发不同信息源，但不是不同产品模式。

## 1.2 多模态是主脑，不是后置增强

从第一阶段开始就接入真实 VLM。

VLM 负责：
- 整图理解；
- 图片类型判断；
- 主要/次要区域理解；
- 对象和区域命名；
- 空间关系；
- 遮挡关系；
- 文字/符号是否重要；
- 哪些结构对“理解这张图”有意义；
- 给 Grounding 模型产生开放词汇 prompt；
- 给 Tactile Planner 产生触觉表达计划。

## 1.3 VLM 不直接输出 pin bits

禁止：

```text
VLM → 3840 个 0/1
```

原因：
- 几何位置不稳定；
- 不可重复；
- 难以验证；
- 难以适配不同设备。

VLM 输出“场景和触觉设计意图”；确定性 Compiler 负责最终矩阵。

## 1.4 完整理解 ≠ 所有视觉细节都凸起

系统必须尽量理解整张图。

但触觉带宽有限，所以需要：

```text
完整理解
→ 信息分层
→ 触觉压缩
```

允许压缩：
- 木纹；
- 头发碎纹理；
- 草地细纹；
- 噪点；
- 阴影变化；
- 高频背景纹理。

不允许因为语义分类而直接删除：
- 主要对象；
- 明显次要对象；
- 大型背景结构；
- 对理解空间关系重要的区域。

## 1.5 单色物理表面

虚拟和未来物理显示都按同一逻辑：

- 所有 pin 同一种银色 / 物理材质；
- 同直径；
- 同间距；
- 不用颜色编码状态；
- 信息只通过几何高度、轮廓、区域结构表达。

# 3. 四个核心数据对象

## 3.1 SceneUnderstanding

来自 VLM。

不是精确像素坐标，而是语义理解。

示例：

```json
{
  "scene_summary": "两个人坐在桌边，右下有一只狗，背景有窗户和植物",
  "content_type": "photo",
  "regions": [
    {
      "id": "person_left",
      "name": "person",
      "approx_location": "left-center",
      "importance": 0.92
    },
    {
      "id": "dog_right",
      "name": "dog",
      "approx_location": "right-bottom",
      "importance": 0.86
    }
  ],
  "relations": [
    ["dog_right", "right_of", "person_left"]
  ],
  "text_regions": [],
  "grounding_prompts": ["person", "dog", "table", "window", "plant"]
}
```

## 3.2 GroundedScene

把 VLM 理解和真实图像坐标对齐。

每个区域保存：

- semantic id；
- bbox；
- mask；
- contour；
- centroid；
- confidence；
- depth order（可选）；
- OCR；
- 结构线；
- 与其他区域的空间关系。

这是整个系统的“事实层”。

## 3.3 TactilePlan

VLM 在看到 GroundedScene 后产生。

它不控制具体 pin，只决定如何表达。

示例：

```json
{
  "regions": [
    {
      "id": "person_left",
      "tactile_role": "primary_object",
      "boundary_strength": 3,
      "internal_structure": 1,
      "fill": "none"
    },
    {
      "id": "window",
      "tactile_role": "supporting_geometry",
      "boundary_strength": 1
    }
  ],
  "preserve_relations": [
    "person_left left_of dog_right"
  ]
}
```

## 3.4 TactileScene

设备无关的正式触觉场景。

它保存的是：

- 主轮廓；
- 次级轮廓；
- 内部关键结构；
- 几何线；
- 区域；
- landmark；
- 高度语义；
- 触觉优先级；
- semantic hit map。

它不等于 80×48。

同一份 TactileScene 可以编译到任何 DeviceProfile。

# 4. 高度模型重新设计

V1 的二值 0/1 不再作为系统内部唯一表达。

内部统一使用 4 个语义高度层：

```text
0 = base / background
1 = supporting structure
2 = secondary / internal structure
3 = primary boundary / landmark
```

重要：

这不是规定“所有前景都必须是 3”。

Tactile Planner 可以按图片决定每个区域如何使用这些层级。

DeviceProfile 决定实际设备如何映射：

### 二值设备

```text
0 → 0
1/2/3 → 1
```

### 四级设备

```text
0 → 0
1 → 1
2 → 2
3 → 3
```

这样当前设备能力不会限制上层产品设计。

# 5. 模型策略

## 5.1 多模态主模型：第一版直接 API

第一正式版本优先：

**Qwen3-VL API**

用途：
1. Scene Understanding；
2. Grounding Prompt 生成；
3. Tactile Planning；
4. 后续 Critic。

原因：
- 不拿 RDK X5 的 3GB 内存强行塞大 VLM；
- 先把产品能力做对；
- API 和本地模型通过 Adapter 隔离，后续可替换。

接口：

```text
MultimodalProvider
├── Qwen3VLApiProvider
├── OpenAICompatibleProvider
├── LocalQwenProvider
└── FutureEdgeProvider
```

### 本地开源备选

开发机 / 服务器：
- Qwen3-VL-4B；
- Qwen3-VL-8B；
- 更大版本按机器资源选择。

端侧探索不是当前主线。

RDK 先承担“精确视觉 grounding + 编译运行时”。

## 5.2 开放词汇定位：RDK

优先接：

**YOLOWorld / RDK X5**

流程：

```text
VLM
→ 输出图片中需要 grounding 的开放词汇
→ YOLOWorld
→ 精确 boxes
```

不依赖固定 COCO 类别表。

## 5.3 通用分割

优先顺序：

### A. RDK YOLOE

首先验证当前 D-Robotics YOLOE runtime 是否支持我们需要的开放词汇 / prompt 工作流。

如果能：
- 直接在 RDK 做开放词汇实例 mask。

### B. YOLOWorld + SAM2

如果 RDK YOLOE 的 prompt 能力不足：

```text
VLM prompts
→ RDK YOLOWorld boxes
→ SAM2
→ masks
```

SAM2 可先运行在开发 PC / 服务端。

这仍然是正式真实模型链，不是模拟。

## 5.4 OCR

RDK PaddleOCR。

文字型图片必须进入统一系统。

VLM 决定：
- 文字是背景；
- 还是图片主要内容；
- 哪些文字需要保留为 tactile marker / 后续语音。

## 5.5 Depth

RDK 可使用官方 monocular depth 模型作为可选信息源。

Depth 只用于：
- 前后关系；
- 遮挡；
- 层次判断。

禁止：

```text
depth value → pin height
```

## 5.6 结构补充

保留：
- Deep Edge；
- LSD；
- Canny / Scharr。

它们是结构补充源。

不是主脑。

# 6. 多模态调用设计

一张图片至少经历两次 VLM 推理。

## Call A：Understand

输入：
- 原始图片。

输出：
- SceneUnderstanding；
- scene summary；
- regions；
- approximate relations；
- open-vocabulary grounding prompts；
- text importance；
- image-type hints。

## Grounding

非语言模型完成：

```text
YOLOWorld / YOLOE / SAM2
OCR
Depth
Deep Edge
LSD
```

得到 GroundedScene。

## Call B：Plan

输入：
- 原始图片；
- SceneUnderstanding；
- GroundedScene 的简化 JSON；
- 可选 segmentation overlay / structural preview；
- DeviceProfile 的能力上限。

输出：
- TactilePlan。

## Optional Call C：Critic

输入：
- 原图；
- Tactile Preview；
- TactileScene summary；
- metrics。

只允许输出：
- 参数调整；
- 某 region tactile_role 调整；
- simplification 强弱；
- layer assignment。

禁止直接输出 pin array。

最多 1～2 次重编译。

# 7. “任意图片”的通用处理原则

系统不按类别硬分支，而是按“信息形态”动态组合。

## 摄影照片

更依赖：
- VLM；
- open-vocab grounding；
- masks；
- depth；
- major geometry。

## 文档 / UI / 截图

更依赖：
- VLM；
- OCR；
- large layout regions；
- separators / boxes。

## 地图 / 图表

更依赖：
- VLM；
- OCR；
- LSD / geometry；
- topology。

## 线稿 / 插画

更依赖：
- VLM；
- Deep Edge；
- segmentation；
- geometry。

## 抽象 / 无明确对象图片

允许：
- VLM 给出整体结构解释；
- structure pipeline 接管；
- 不强行虚构具体对象。

这是统一 pipeline 的动态路由，不是预定义“模式”。

# 10. 开发阶段

## M0｜架构纠偏与数据契约

目标：让工程从“图像→边缘→点阵”升级成“多模态场景→触觉编译”。

必须完成：

- MultimodalProvider；
- SceneUnderstanding schema；
- GroundedScene schema；
- TactilePlan schema；
- TactileScene schema；
- multi-level height；
- 原来的 Sobel 浏览器链降级成 debug fallback。

完成标准：

项目代码里不存在“浏览器自己就是主 Compiler”的逻辑。

## M1｜第一版真正可用的通用多模态产品

正式链：

```text
真实 JPG / PNG
→ Qwen3-VL API
→ SceneUnderstanding
→ RDK YOLOWorld
→ real grounding
→ segmentation backend
→ GroundedScene
→ Qwen3-VL TactilePlan
→ TactileScene
→ Device Compiler
→ Silver Surface
→ RDK HDMI
```

没有模型的步骤不允许用假数据冒充。

完成标准：

至少十种不同类型真实图片均能走完整条链。

## M2｜通用 Mask 与结构完整性

完成：

- RDK YOLOE 能力验证；
- SAM2 adapter；
- Deep Edge；
- LSD；
- OCR；
- Grounding merge；
- mask / line / OCR / depth 坐标统一。

重点：

解决“VLM 看懂但没有精确几何”的断点。

## M3｜触觉语言

这一阶段解决真正核心问题：

> AI 知道图片以后，到底应该怎样让手理解？

实现：

- primary boundary；
- secondary boundary；
- internal structure；
- landmark；
- supporting geometry；
- background structure；
- 0/1/2/3 height semantics；
- simplification；
- collision separation；
- small-region compensation。

不直接以“对象类别”决定触觉样式。

## M4｜Critic 自适应重编译

VLM 看：

```text
Original + Tactile Preview
```

判断：
- 是否丢大结构；
- 是否太密；
- 是否对象粘连；
- 是否背景压过主体；
- 是否结构过度简化。

最多自动重编译两次。

## M5｜产品化

完成：
- 摄像头 / Insta360 input adapter；
- 图库输入；
- RDK 独立运行时；
- 网络 API 配置；
- 缓存；
- 超时；
- API 失败降级；
- telemetry / trace；
- 后续 Touch Hit Map；
- 后续语音。

# 13. 核心指标

不是只看 IoU。

产品级指标：

### Scene Coverage
VLM 提到的重要区域，有多少在 GroundedScene 中真正落地。

### Structural Coverage
图像主要结构在 TactileScene 中保留多少。

### Relation Preservation
左右、上下、包含、遮挡、相邻关系是否保留。

### Tactile Density
输出是否过密。

### Fragmentation
是否产生大量碎点。

### Separation
相邻对象是否在低分辨率下粘连。

### Repeatability
同一输入重复编译，核心空间结构是否稳定。

### Cross-device Consistency
同一 TactileScene 编译到不同设备后，空间关系是否一致。

# 14. 失败与降级

“通用”不能靠假装每个模型都不会失败。

必须设计真实降级：

```text
VLM 成功
Grounding 失败
→ VLM + structural fallback

开放词汇检测遗漏
→ Deep Edge / SAM2 补结构

Segmentation 失败
→ boundary / geometry route

OCR 图片
→ OCR + layout 优先

API 暂时不可用
→ local structural compile
→ 标记 degraded mode
```

任何情况下：
- 不崩；
- 不输出空白；
- 不假装识别成功；
- Developer UI 要显示哪一层失败。

# 15. 明确禁止

后续开发禁止再出现：

- Sobel-only 作为主产品算法；
- 固定 3～5 个对象；
- 只支持 COCO 固定类别；
- VLM 直接输出 pins；
- depth 直接映射高度；
- 先缩成 80×48 再做理解；
- 主体裁剪；
- 拉伸原图；
- 按“背景”语义整块删除；
- 用黑白 / 颜色区别 pin 状态；
- synthetic 图片作为主要验收；
- 为了端侧而不用真正能解决问题的模型；
- 为了“先能跑”绕开多模态。

# 16. 当前选择

当前正式路线：

```text
Qwen3-VL API
       ↓
SceneUnderstanding
       ↓
RDK YOLOWorld + Segmentation + OCR
       ↓
GroundedScene
       ↓
Qwen3-VL Tactile Planner
       ↓
TactileScene (0/1/2/3 semantic height)
       ↓
Device Compiler
       ↓
RDK / Virtual Silver Pin Surface
```

SAM2、Deep Edge、Depth、Critic 作为随后并入的真实能力，不改变核心数据契约。

这个架构允许未来替换成：
- 更强云端 VLM；
- Qwen3-VL 本地版本；
- 其他开源 VLM；
- OpenAI-compatible multimodal API；
