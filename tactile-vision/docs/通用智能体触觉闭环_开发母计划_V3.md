# 通用智能体触觉闭环｜开发母计划 V3.0（已废止）

> **废止通知（2026-09-23）：** V3 仍让本地 DeviceCompiler 从设备无关几何生成最终 pin，与模型直接负责每个点位的要求冲突。当前唯一有效计划为 [通用多模态智能体触觉闭环_开发母计划_V4.md](./通用多模态智能体触觉闭环_开发母计划_V4.md)。本文件仅保留历史记录。

状态：**当前唯一有效主计划**  
日期：2026-09-22  
替代：V2.0、V1.1 及更早的 Sobel / Grounding-first 路线

## 0. 一句话产品定义

把任意真实图片交给顶级多模态模型与智能体，由智能体理解完整场景并设计触觉表达，再把设计编译成当前设备上每一个 pin 的高度与交互语义；屏幕实时模拟全部 pin 的升起、稳定、落下和再次复用，用户触摸某个区域时系统进行语音说明，并允许继续追问。

```text
任意真实图片
→ 顶级多模态模型完整理解
→ 智能体设计可执行 TactileProgram
→ DeviceCompiler 落到每一个 pin
→ 屏幕/RDK 动态模拟整面触觉阵列
→ 触摸命中语义区域
→ 语音说明 + 连续问答
```

这是一条端到端软件闭环。传统边缘检测、目标检测、分割和深度模型都不是主链的固定关卡。

## 1. 本次纠偏的核心结论

### 1.1 通用性来自大模型与统一数据契约

产品默认面对任意图片，而不是固定人物、动物、斑马、课堂卡片或 COCO 类别。

统一支持人物、动物、室内、街景、建筑、风景、植物、商品、文档、UI、海报、地图、图表、线稿、插画和抽象图像。

若黑客松阶段的时延或稳定性不足，可以把验收数据集暂时收敛到“小学教育中的单主体认知”，但这只是演示范围收敛，不允许把系统架构改成单类别检测器。

### 1.2 智能体必须对最终 pin 负责

智能体不能只输出一段场景描述后停住，也不能把“最后哪些点升起”全部推给与语义无关的传统算法。

智能体需要输出：

1. 图片完整语义；
2. 主要和辅助结构的准确位置；
3. 哪些结构应该触觉化；
4. 各结构的触觉高度、轮廓、填充和层级；
5. 每个触觉区域的语音说明；
6. 可由 DeviceCompiler 确定性展开到每一个 pin 的几何指令；
7. 每个 pin 对应的语义命中信息。

DeviceCompiler 只做坐标变换、裁界、冲突处理、设备适配和协议编码，不替智能体做语义选择。

### 1.3 不再设置强制 Grounding 绕行

以下路线废止为固定主链：

```text
VLM → 必须 YOLOWorld → 必须 SAM/Segmentation
→ 必须 Edge Fusion → 才能输出触觉图
```

它让已经能进行视觉理解和空间推理的顶级模型，被迫经过多套局部算法重复理解，并把通用系统重新限制成检测/分割流水线。

正确策略：

```text
Agent 默认直接完成理解与触觉设计
          ↓
只有当 Agent 判断坐标精度不足时，才按需调用检测、分割、OCR、深度或边缘工具
```

YOLO、SAM、OCR、Depth、LSD、Canny 等可以保留为 Agent Tools 或失败兜底，但不得成为每张图片必经的产品步骤，不得挡住闭环。

## 2. 正式架构

```text
Product UI
上传/相机 → 生成 → 动态针阵 → 触摸 → 语音 → 继续追问
                         │
                         ↓
Multimodal Tactile Agent
完整场景理解 + 空间建模 + 触觉设计 + 交互语义
可选工具仅在需要时调用
                         │ TactileProgram
                         ↓
Deterministic DeviceCompiler
坐标归一化 → DeviceProfile → pin heights → hit map → 协议
                         │
            ┌────────────┴────────────┐
            ↓                         ↓
  Web Silver Surface               RDK HDMI
  动态升降与触摸模拟                 现场展示运行时
            └────────────┬────────────┘
                         ↓
                Speech + Follow-up Agent
```

## 3. 核心数据对象

### 3.1 SceneUnderstanding

智能体对整张图片的完整理解，包括图片类型、整体摘要、场景元素、大型背景结构、元素关系、文字/符号/图表信息和不确定项。

它是智能体内部与 Developer Trace 的可解释信息，不是最终产品输出。

### 3.2 TactileProgram

智能体的主要可执行输出。它与设备无关，但必须足够精确地展开到每一个 pin。

```json
{
  "version": 1,
  "scene_summary": "图片的整体说明",
  "audio_overview": "首次可播放的整体语音",
  "canvas": {"coordinate_space": 1000, "orientation": "landscape"},
  "regions": [
    {
      "id": "stable_region_id",
      "name": "区域名称",
      "description": "对用户有意义的说明",
      "speech": "触摸该区域时播放的短句",
      "importance": 0.95,
      "height": 3,
      "geometry": {
        "type": "polygon|polyline|ellipse|rect|point|pin_mask",
        "points": [[120, 180], [340, 160]],
        "bbox": [120, 160, 340, 620],
        "thickness": 2,
        "fill": "none|sparse|solid"
      }
    }
  ],
  "supporting_structures": [],
  "warnings": []
}
```

如果模型能稳定输出设备级 pin mask，允许使用 `pin_mask`；如果直接输出完整点阵不稳定，则使用精确归一化几何，由确定性编译器展开。两种方式都要求智能体决定触觉含义和空间位置，而不是由传统视觉算法替它决定。

### 3.3 TactileFrame

设备级完整状态包括 `cols × rows`、每个 pin 的目标高度、frame id、版本、校验信息和 DeviceProfile。

当前已确认逻辑网格为 **80×48，共 3840 个 pin**。口头所说的约 4096 个点代表整面点阵概念；实际数量必须以 DeviceProfile 为准，不能在代码中写死 4096。

```text
0 = 完全落下
1 = 辅助结构
2 = 次级轮廓 / 内部结构
3 = 主轮廓 / 关键触觉点
```

二值物理设备可在最后映射为 0/1，但产品内部保留多级触觉语义。

### 3.4 InteractionMap

InteractionMap 与 TactileFrame 同尺寸，每个 pin 记录 region id、region name、短语音说明、对话上下文引用和是否为可触摸 landmark。

用户触摸任意位置时，系统立即知道“触摸到了什么”，不重新做一次图像识别。

## 4. 模型与智能体策略

### 4.1 当前主模型

使用用户已提供业务空间中的顶级多模态模型，当前目标为 `qwen3.8-max`。

密钥只保存在本地私密配置中，不进入浏览器、不写入文档、不由状态接口返回。

### 4.2 一次主调用完成设计

第一版优先让一次多模态调用同时输出 SceneUnderstanding 摘要、TactileProgram、audio overview、region speech 和 follow-up context。

避免为了形式把一次可以完成的任务拆成多次模型调用和多套重复视觉流水线。

### 4.3 工具调用原则

允许模型按需调用 OCR、高精度检测/分割、Depth、Edge/Line 和联网知识。

工具服务于 Agent 的最终触觉决策，不建立第二套与 Agent 竞争的固定主脑。新增工具必须由真实失败样例证明收益。

## 5. 页面与动态触觉表面

### 5.1 Product UI

产品页必须一眼看懂，不展示算法堆栈：

```text
选择图片
→ AI 正在理解并设计触觉图
→ 针阵动态升起
→ 可以触摸探索
→ 复位 / 再次播放 / 换图
```

主页面只保留原始图片、生成按钮与真实进度、银色 3D pin surface、整体语音说明、当前触摸区域说明、继续追问输入，以及 `全部落下 / 重新升起 / 换一张`。

### 5.2 必须展示真实运动过程

```text
LOWERED → RISING → EXPLORE_READY → RETRACTING → LOWERED
```

要求：

- 新图片生成前，上一帧先落下；
- 新帧不是瞬间替换，要看见各 pin 升起；
- 支持一键全部落下；
- 支持同一帧再次升起；
- 支持不同图片连续复用；
- 运动过程中显示明确状态，不伪装完成。

### 5.3 Developer UI

开发信息放入折叠面板或独立页面，不得压过产品体验。可展示原始模型 JSON、TactileProgram、最终 pin matrix、InteractionMap、模型/耗时/token/错误和实际调用的可选工具。

不再在 Product UI 中把 `GroundedScene / YOLOWorld / Segmentation` 显示成必经但未完成的步骤。

## 6. 触摸、语音与连续对话闭环

### 6.1 首次说明

生成完成后可播放简短 overview，例如：“这是一张公园照片。左侧是一棵树，中间有人，右下有一只狗。你可以从左向右触摸。”

### 6.2 区域触摸

```text
pin coordinate → InteractionMap → region id → 本地即时短说明 / TTS
```

### 6.3 继续追问

用户可以问“这个地方是什么”“它和左边是什么关系”“再详细解释”“整张图还有什么”。对话上下文包含当前图片、TactileProgram、当前触摸 region 和历史对话。

## 7. 失败与降级

必须诚实显示失败层，不得用假结果冒充模型成功。

```text
主模型成功 → 正常生成 TactileProgram 和完整交互闭环
主模型返回可修复 JSON → 校验器修复格式并记录 warning
主模型暂时不可用 → 显示 API 错误，可重试或使用缓存
```

离线边缘或检测结果只能标记为 `degraded fallback`，不得伪装成通用智能体输出。

## 8. 执行里程碑

### M0｜计划与页面纠偏（当前）

- 本计划成为唯一有效主计划；
- 旧计划标记废止；
- Product UI 删除固定 Grounding/算法关卡；
- 页面明确最终输出和运动状态。

Gate：团队任何人都能用一句话准确说出主链，不再出现两套路线。

### M1｜任意图片到动态针阵

- 接通已提供的 `qwen3.8-max` API；
- 定义并校验 TactileProgram；
- DeviceCompiler 生成 80×48 多级 TactileFrame；
- 3D pin surface 动态升起、落下和重放；
- 页面显示模型真实结果和错误。

Gate：至少 10 种不同图片完成 `图片 → AI → 全部 pin → 动态表面`，中间不依赖手写类别。

### M2｜触摸与语音闭环

- InteractionMap；
- 点击/触摸 pin 命中 region；
- overview、region speech 和 TTS；
- 基于当前触摸位置的连续问答。

Gate：用户闭眼时能通过触摸与语音获得图片整体和局部信息。

### M3｜RDK 现场运行

- PC/服务端负责模型调用与 Agent；
- RDK 接收 TactileFrame 和 InteractionMap；
- HDMI 展示同一动态银色触觉表面；
- 协议支持复位、升起、重放和新帧。

Gate：PC 与 RDK 展示同一帧、同一运动状态和同一区域语义。

### M4｜精度工具与性能优化

- 只针对真实失败样例添加可选工具；
- 比较模型直接空间输出与检测/分割辅助的真实收益；
- 缓存、重试、超时和成本控制；
- 必要时建立小学单主体演示集，但保持统一 TactileProgram。

Gate：新增工具必须证明提升失败指标，不能仅因为“算法常见”进入主链。

## 9. 验收集与指标

通用验收至少覆盖单人物、多人、动物、室内、街景、建筑、植物、商品、文档/UI、地图/图表和线稿/插画。

核心指标：

- Semantic Coverage：重要内容是否进入 TactileProgram；
- Spatial Fidelity：空间关系是否正确；
- Pin Intent Coverage：每个升起 pin 是否有可解释来源；
- Touch Explainability：触摸有效区域是否正确说明；
- Motion Completeness：升起、稳定、落下、复用是否完整；
- Cross-device Consistency：不同 profile 上关系是否一致；
- End-to-end Latency：上传到可探索状态的真实耗时；
- Repeatability：重复生成时核心结构是否稳定。

## 10. 明确禁止

- 把 Sobel、Canny、YOLO、SAM 或任意单一算法重新设为产品主脑；
- 把 GroundedScene 设成阻塞所有图片的固定关卡；
- 只显示 SceneUnderstanding 文本却不生成触觉表面；
- 用 synthetic frame 冒充模型闭环；
- 让浏览器偷偷执行另一套 Sobel 主编译逻辑；
- 按固定类别删除模型没有预设的对象；
- 写死 4096、64×64 或其他点阵尺寸；
- 瞬间替换画面而不展示 pin 升降；
- 触摸后无法说明当前区域；
- 页面堆满未完成算法模块，却没有用户可用闭环。

## 11. 当前立即执行顺序

1. 旧计划全部标记废止并指向本计划。
2. Product UI 改成 `图片 → AI 触觉生成 → 动态针阵 → 触摸/语音`。
3. 定义 TactileProgram 与 InteractionMap schema。
4. 用已提供 API 完成真实图片到 TactileProgram 的一次主调用。
5. 实现 DeviceCompiler，落到当前 80×48 的每一个 pin。
6. 修好银色针阵的升起、落下、复位和重放动画。
7. 实现 pin/region 命中与浏览器 TTS。
8. 接连续追问 API。
9. 把同一结果推送到 RDK HDMI 页面。
10. 用通用图片集做端到端回归；只有真实失败样例才触发可选精度工具开发。

最终判断标准不是“用了多少算法”，而是：一张任意图片进来后，用户能否看到整面针阵真实运动，能否触摸理解，能否听到说明，能否继续提问，并能重复复用这块触觉表面。
